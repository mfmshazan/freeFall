# NASA data access and experimental coverage

Start with two small acquisitions that answer different product questions. BASS-II gives Flame in Freefall a path from an existing replay to a documented comparison under different ventilation. The Lunar Combustion Investigation (LUCI) gives it a measured partial-gravity example. A browser helper can reduce the work of retrieving these files. Each new run still needs an experiment-specific mapping and measured outputs before it can validate the simulator.

## Current application

- The React dashboard has a cabin builder, flame animation, trust gauge and uncertainty halo, four ranked experiment matches, a rules-based fire-safety playbook, and an Earth applications panel. It calls FastAPI and falls back to a local physics model in the browser. The backend uses three Gaussian processes for spread rate, flame length, and flame width. The physics formulas provide the other outputs. [Dashboard](frontend/src/App.tsx), [Backend prediction](backend/main.py).
- The two replay views already provide experimental evidence. Saffire-I synchronizes 80 flight frames from a partial image archive to measured telemetry. BASS-II has both B1 and B3 videos and proof sheets in the checked-in replay, plus a side-by-side conditions view. The [inventory](DATA_INVENTORY.md) still describes B3 as a proposed acquisition. The original download directory is absent from this checkout. B1 and B3 have before/after gas readings and independent video playback clocks. [Saffire-I replay](frontend/src/replay/SaffireReplay.tsx), [BASS-II comparison data](frontend/public/replay/bass-2/compare.json).
- Both master JSON copies contain identical records. There are 24 seeds and two Saffire-I rows with sourced conditions and `physics_estimate` outputs. The Saffire rows represent concurrent and opposed spread. Flow direction travels with the evidence row but is absent from the model inputs and ranking distance. For a controlled comparison, also retain specimen geometry, orientation, and apparatus. [Master dataset](backend/data/psi_master.json), [Experiment ranker](backend/ranker.py), [Predictor inputs](frontend/src/types.ts).

## Public entry points

- **BASS-II, PSI-25.** The connected browser returned an unavailable message for the route, while NASA's indexed record still identifies PSI-25 Version 4. Treat this as a route/session compatibility issue until a current PSI/BPS page or export is verified. NASA’s public technical memorandum remains usable for experiment variables and sensor context, and the repository already contains the B1/B3 replay assets. [PSI-25 route](https://psi.nasa.gov/physci/repo/data/investigations/PSI-25), [BASS-II summary report](https://ntrs.nasa.gov/citations/20210011385).
- **PSI file selection.** Start at the investigation page, find the Experiment Table and Data Files and Documents, and select individual files. NASA's guide documents the table download and the selectable file tree, including Earth and reduced-gravity folders where applicable. The repository's [download checklist](DOWNLOAD_CHECKLIST.md) expects the experimental CSV and ISA-Tab `i_Investigation.txt`. Confirm the actual file formats and names per investigation. NASA routes large ZIP requests over 1 GB through emailed, expiring links. [PSI database guide](https://assets.science.nasa.gov/content/dam/science/bps/bps-general/bps-data_osdr_psi/Complete_PSI_Database_Guide.pdf), [NASA large-download announcement](https://science.nasa.gov/uncategorized/new-file-download-process-for-large-requestspsi-new-file-download-process/).
- **NASA Technical Reports Server (NTRS).** Use it for directly discoverable reports and measured results published as figures or tables. NASA documents an API for citation search and downloads. A report can establish outputs, units, and limitations while the raw assets are being located. [NASA NTRS API documentation](https://sti.nasa.gov/docs/20221122_OpenAPI_Documentation.pdf).

## Acquisition order

1. **BASS-II for a same-family airflow comparison.** Start with the existing B1/B3 replay assets, the test matrix and data FAQ identified in the [inventory](DATA_INVENTORY.md), and the PSI export and metadata if available. The comparison documents the runs' differing post-test gases and image coverage. Check video calibration and preserve channel timing before deriving flame dimensions or spread rates. [PSI-25 investigation](https://psi.nasa.gov/physci/repo/data/investigations/PSI-25), [BASS-II summary report](https://ntrs.nasa.gov/citations/20210011385).
2. **LUCI for a partial-gravity anchor.** NASA reports a rotating sounding-rocket test at simulated lunar gravity with a PMMA rod and cotton-fiberglass fabric, two camera views, and a chamber oxygen measurement. The report includes measured spread results and shows rotation-related asymmetry in one view. Preserve `simulated lunar gravity`, the direction of the applied acceleration relative to the specimen, the sample geometry, and the measurement definition when using a point from this study. Seek the matching Earth trial for a controlled comparison and record known setup differences. A separate BASS-II rod study provides measured spread and images on Earth and the ISS with explicit apparatus differences. That is a two-gravity comparison for rods, while B1/B3 is a same-gravity comparison for film. [LUCI report and figures](https://ntrs.nasa.gov/citations/20250010653), [BASS-II PMMA rod study](https://www.nature.com/articles/s41598-017-18398-4).
3. **BASS-II and SoFIE GEL for atmosphere effects.** BASS-II explicitly studies reduced oxygen by nitrogen dilution and records sample geometry and ventilation. NASA's SoFIE GEL results provide a separate data source for PMMA spheres where oxygen and airflow varied at one total pressure. Use a single test geometry and known atmosphere for the first comparison. Train separate relationships when a dataset changes fuel or geometry. Additional pressure or diluent effects require separate experiments with those variables measured or controlled. [BASS-II summary report](https://ntrs.nasa.gov/citations/20210011385), [SoFIE GEL report](https://ntrs.nasa.gov/citations/20240007628).
4. **ACME Flame Design and SPICE for visual examples.** ACME Flame Design studies soot in gaseous spherical flames. SPICE has imagery, luminous flame lengths and Earth/ISS comparisons for gas jets. Use the images for named qualitative cases and keep gas-jet results attached to their burners and fuels. Treat observed RGB color as camera-dependent unless settings and calibration support quantitative comparisons. The NASA ISS soot photograph also gives an example of why gravity alone cannot set a flame's color. [ACME Flame Design](https://science.nasa.gov/biological-physical/investigations/flame-design/), [SPICE, PSI-107](https://psi.nasa.gov/physci/repo/data/investigations/PSI-107), [NASA ISS soot image](https://science.nasa.gov/image-article/apod-2021-august-10-fire-in-space/).
5. **Saffire for measured large-scale outcomes.** Saffire-I's PSI record lists published spread analyses and camera calibration records. Saffire IV and V reports describe measured flame spread, temperature, and radiative heat alongside cabin sensor readings. Use published measurements by run, and preserve the distinction between a local sensor reading and a flame measurement. [Saffire-I, PSI-98](https://psi.nasa.gov/physci/repo/data/investigations/PSI-98), [Saffire IV/V results](https://ntrs.nasa.gov/citations/20210017780).

NASA gives a gravitational field at roughly ISS altitude of 89% of surface gravity. The inverse-square relation for a spherical Earth gives a field strength relative to the surface of `(R / (R + h))²`, where `R` is Earth's radius and `h` is altitude. Cabin buoyancy responds to effective acceleration relative to the cabin, which is near zero in free fall and can change with maneuvers or rotation. Show field strength versus altitude as its own calculation. Give independent presets for a stationary Earth lab, an orbiting cabin, and supported Moon and Mars habitats (roughly 0.165 g and 0.38 g). Distinguish simulated gravity from a planetary surface measurement. Forced ventilation remains relevant when buoyant convection is weak. [NASA microgravity explanation](https://www.nasa.gov/centers-and-facilities/glenn/what-is-microgravity/), [NASA Moon gravity](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/moon/), [NASA Mars fact sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/marsfact.html).

For cabin composition, store oxygen fraction, total pressure, and the measured balance gases independently. Oxygen partial pressure is the product of oxygen fraction and total pressure. Gas composition can change heat and mass transport, soot or emission, and the visible shape. The offline model currently lets oxygen and pressure change size through its oxygen partial-pressure index. Aspect ratio is driven by effective gravity and airflow speed. The diluent selector changes heuristic spread and soot multipliers and cannot represent a mixed balance gas. The displayed color is a palette chosen from modeled soot and regime. [Offline model](frontend/src/physics/flameModel.ts), [NASA study of diluent effects](https://ntrs.nasa.gov/citations/19990054043), [FlameCanvas](frontend/src/components/FlameCanvas.tsx).

## Import and validation

The [current importer](backend/ingest_psi.py) assumes Saffire-style CSV headers, assigns zero gravity in both platform branches, defaults total pressure to 14.7 psi and the diluent to nitrogen, and fills flame outputs with the physics model. The [surrogate](backend/surrogate.py) fits every master record plus synthetic anchors, including records whose outputs come from that model. Running the same importer against more condition tables increases case coverage. A comparison against independent output measurements is the milestone for testing accuracy.

For an initial curated run, retain the PSI identifier or report citation, version, run ID, source file or figure, material and geometry, gravity source and direction, flow direction and speed, total pressure, oxygen, reported diluent composition, and measurement units. Track which fields were measured, derived from imagery, assumed, or missing. Use source files as read-only inputs, stage them outside the frontend bundle, and review a single-run import before committing normalized records. Hold a measured run out of fitting before reporting accuracy for that case family.

The [challenge brief](https://www.spaceappschallenge.org/2026/challenges/flame-in-freefall/) asks for an interactive dashboard that summarizes, ranks, and interprets combustion data. The closest release is a dashboard with cited experiment matches, real replay, and an illustrative scenario explorer with explicit limits. Base the evidence indicator on measured outcomes under comparable conditions. The current confidence text can call a seed record real, the 95% halo has no demonstrated experimental coverage, and the recommended safety multipliers are fixed by status. Label coverage and uncertainty accordingly. [Backend confidence logic](backend/main.py), [Offline confidence logic](frontend/src/physics/localService.ts), [Trust gauge](frontend/src/components/TrustGauge.tsx).

## Browser and MCP feasibility

The first 30-minute milestone is one complete test on PSI-25. Open the live investigation in the available browser, select one small artifact, verify its completed local file, and attach an acquisition record with the source URL, version, filename, and destination. If the current browser can do this, it already covers acquisition for a handful of investigations. A browser session still depends on NASA having published the desired files and on any session access NASA requires.

If a local MCP connection is useful for repeated browser work, Google's existing Chrome DevTools MCP can start a fresh browser session or attach to a supported Chrome session with user consent. A dedicated research profile keeps unrelated signed-in sites out of that session. Verify one PSI download and its local path before adopting it as the handoff. [Chrome DevTools MCP configuration](https://developer.chrome.com/docs/devtools/agents/get-started/configuration/).

An unpacked Manifest V3 extension is a plausible small prototype for repeated use. A click on the active PSI tab could capture visible investigation information, show the selected files, and export a manifest while NASA's own download control handles transfers. `activeTab` grants temporary access when the user invokes the extension. Chrome's downloads API can monitor completed transfers and its suggested destination path is relative to Downloads. A local importer can stage validated files in the repository. Real PSI file selection and download completion need a live test before calling that workflow reliable. [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [Chrome Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads).

For agent integration, a local MCP server can first read acquisition manifests and preview or stage files in a defined local directory. If the extension eventually needs to communicate directly with a local process, Chrome's native messaging requires registering a separate host with an allowed extension ID. That adds browser and OS setup, framing and permissions, plus end-to-end testing. Keep the first experiment usable with the browser and an explicit local file handoff. [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [OpenAI MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
